# 统一型号与跨平台选号

`GET /v1/models` 默认每个统一型号只返回一条记录。调用裸型号（例如 `glm-5.2`）时，从当前密钥有权使用、支持该型号且符合地区、冷却、并发等条件的账号中自动选择。每次实际调用都转换成所选账号目录中的原名，失败重试换平台时重新转换。

## 合并范围

| 原始写法示例 | 统一名称 |
| --- | --- |
| `GLM-5-2`、`glm.5.2`、`GLM_5_2` | `glm-5.2` |
| `claude-sonnet-4-5`、`claude-4.5-sonnet` | `claude-sonnet-4.5` |
| `deepseek-v3-2`、`deepseek-v3.2` | `deepseek-v3.2` |

这里只规范已知型号的拼写，不能凭名称相似确认上游实际使用相同权重。日期、Harmony、SFT、preview、test、pro、flash、参数规模等后缀全部保留；`qwen3-32b` 不会变成小数版本。未知名称只统一大小写、空格和下划线。`auto`、`default`、`speed` 等自动选型策略保留平台前缀，不视为固定模型跨平台合并。

## 目录和界面

```json
{"id":"glm-5.2","object":"model","owned_by":"relaypool","providers":["officeace","workbuddy"],"variants":[{"provider":"officeace","model":"glm.5.2","id":"officeace/glm.5.2"},{"provider":"workbuddy","model":"GLM-5-2","id":"workbuddy/GLM-5-2"}]}
```

以上为结构示例，不代表所有账号都有这些型号。聊天选择器标注可自动选号的平台数，并可展开平台与原始名称；搜索支持平台和原名。概览的“上游型号”仍按账号目录原始名称去重统计，与统一目录条数可能不同。

## 固定平台、权限与兼容

- 使用 `workbuddy/glm-5.2` 固定平台；使用固定账号入口则只调用该账号。原来的平台原名仍能使用。
- 统一名称不会放宽账号或模型白名单。`workbuddy/glm-5.2` 权限只允许 WorkBuddy；裸型号权限可匹配各平台同一型号，但仍受账号白名单限制。
- 可重试错误沿用原有重试次数、地区和健康策略；开始向客户端输出流后，不切换平台拼接回答。没有可用账号时返回错误，不替换为别的型号。
- `/v1/models?view=legacy` 返回旧式目录，供依赖渠道别名的客户端过渡。新客户端优先使用默认目录及 `variants`。
- `cross_provider_pool` 是遗留配置字段，当前路由不读取它。用平台前缀或账号／模型权限限制渠道，不能依赖该字段隔离平台。

## 验证范围

自动化回归覆盖三个协议的流式／非流式跨平台重试、平台原名转换、权限隔离、目录去重和语义后缀保留。实际可用模型以账号权限和上游响应为准，目录存在不等于全部推理功能已经验证。
