# 福利中心

入口：管理台侧栏「福利中心」（`/console/#/benefits`）。

## 发现福利

从 [AI 羊毛牧场](https://github.com/accesaver-byte/ai-yangmao) 的公开只读接口查询福利，展示平台、额度说明、福利类型、领取条件、截止时间、活动状态和最后核验时间。支持关键词、用途、状态筛选和分页；「查看怎么领」读取完整步骤、额度有效期和官方出处。

默认包含待核实信息。来源的 `stale` 会显示为「待重新核实」，不等同于现在可领；来源未说明资格或截止时间时保留未知。应用内积分、API 额度、会员权益和充值赠送按原始说明展示，不进行 Token 或金额折算。

后端每个查询缓存 15 分钟，最多 64 项。上游失败时仅使用 24 小时内旧缓存并标明；没有缓存时显示错误，已接入账号的领取仍可用。来源快照和覆盖不完整也会明确提示。缓存只在内存中，服务重启后重新获取。

列表必须包含有效数组（允许空数组），每项须有非空字符串编号；详情必须包含对象且编号与请求一致。空值、结构错误和不匹配的详情按来源失败处理，不覆盖旧快照。等价分页数字统一后参与缓存键计算，例如 `offset=00` 与 `offset=0` 复用同一结果。

仅查询词和筛选条件发送到公开目录，账号名称、密钥、登录态、余额和领取记录不会发送给该来源。第三方内容按文本展示，外链仅允许不含用户名密码的 HTTPS 地址。外部目录提供的信息不能触发领取、运行脚本或选择账号。

## 我的领取

根据账号池实际返回的领取能力显示账号。当前能力覆盖 WorkBuddy、Qoder、TRAE 国内版、华为云码道和果办；具体地区、登录材料和资格由适配器及上游决定。

1. 先在账号池接入并启用自己的账号。
2. 打开「我的领取」，选择对应账号的「一键领取」。
3. 查看结果：领取成功、已经领过、未确认领取或领取失败。
4. 通过「账号与额度」查看上游余额，或管理该账号已有的后台自动领取设置。

这一步复用原有 `POST /admin/accounts/{id}/checkin`，并由原调度器执行并发保护、凭证续期和结果保存。不会把请求已发送当作到账成功，也不根据目录上的宣传额度修改余额。页面读取和刷新不会发起领取。

前端阻止同一账号重复点击，并按渠道时区及领取周期显示已领状态（例如 Qoder 的北京时间 10 点边界）。停用账号、未配置凭证或账号列表读取失败时禁用领取。换日或在其他页面领取后，可点击「刷新领取状态」。

其他福利提供「查看官方领取说明」入口，由用户在平台完成登录、实名或申请；不支持通用的自动注册、充值或任意第三方网页领取。

## 管理接口

- `GET /admin/benefits`：`q`（最多 120 字）、`modality`（text/code/image/video/audio）、`status`（all/claimable/stale）、`offset`（0–10000）；固定每页最多 12 条，分页使用来源返回的 `nextOffset`。
- `GET /admin/benefits/{id}`：读取单条完整详情，ID 仅允许字母、数字、下划线和短横线。

二者都要求管理密钥，响应包含 `source`、`source_url`、`fetched_at`、`stale` 和 `data`。仅请求固定的 `https://ai-yangmao.com/api/agent/` 路径，不跟随重定向；12 秒超时，响应上限 1 MiB。查询失败返回通用错误和 `Retry-After: 60`，不暴露底层网络错误。

## 验证

`node scripts/benefits-check.mjs` 使用合成账号验证领取结果、重复点击、周期切换、权限条件、分页与旧响应隔离；`go test ./internal/api -run TestBenefits` 验证管理权限、出站数据隔离、查询边界、缓存合并与失联处理。并发检查使用 `go test -race ./internal/api -run TestBenefits`。这些检查不领取真实平台福利。
