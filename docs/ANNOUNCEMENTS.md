# 更新公告

工作台每次打开或刷新，在管理连接验证成功后展示当前版本公告。同一次打开过程中，切换页面不重复弹出；顶部“更新公告”按钮可以重新打开。关闭按钮和 Esc 都能关闭弹窗，键盘焦点限制在弹窗内。关闭记录不写入浏览器存储，因此同一版本下次打开仍会展示。

弹窗内“查看历史公告”可直接定位到历史列表。列表按版本由新到旧排列，每条显示版本、日期和标题，点击或用键盘展开后可阅读完整说明。已归档 `2026.11.16`、`2026.11.16.1`、`2026.11.16.2` 三个版本的原公告；历史内容不替换首次打开时展示的最新公告。

## 维护内容

编辑仓库的 `internal/api/announcements.json`，将公告与本次功能改动一起提交发布。这个文件是公告内容的唯一来源，不需要在界面、数据库或用户浏览器里逐一修改。

| 字段 | 内容 |
| --- | --- |
| `release` | 给用户看的版本标识，例如 `2026.11.16` |
| `published_on` | 发布日期，格式为 `YYYY-MM-DD` |
| `title` | 本次更新标题 |
| `summary` | 一段简短说明 |
| `changes` | 更新条目，每项包含 `title` 和 `description`，至少一项 |
| `history` | 历史版本数组，由新到旧排列；每项使用上述五个字段，不再嵌套 `history` |

所有文字都按纯文本展示，不执行 HTML。建议每次公告控制在 3–5 项，用用户能看懂的语言说明新增能力或修复的问题；完整历史继续保存在 `CHANGELOG.md`。

发布下一版时，先将当前五个内容字段原样移入 `history` 首项，再更新顶层内容。已有历史不得被覆盖，版本标识不得重复，同一天的不同版本使用递增后缀。新前端兼容没有 `history` 的旧接口；旧前端仍可读取顶层最新公告。

校验运行 `node scripts/announcements-check.mjs` 和 `go test ./internal/api -run TestAnnouncements`，覆盖历史完整性、重复版本、旧接口兼容、关闭重开、旧响应隔离及管理权限。

## 用户如何获取新公告

公告在编译时嵌入程序，展示的内容与正在运行的程序保持一致。按[备份与维护](OPERATIONS.md)备份后，用户在项目目录更新代码并重建：

```console
git pull --ff-only
docker compose up -d --build
```

完成后重新打开或刷新工作台，就会看到新版公告。只下载代码、但仍运行旧容器或旧二进制，不会更新弹窗内容。无需清理浏览器缓存或修改数据卷。

若只更新公告文字，不需要重新生成网页资源；重新编译 Go 程序或构建容器即可。修改弹窗样式或交互时，先运行 `node scripts/build-web.mjs`，将 `web/dist/` 与 `internal/api/console/` 的变动一并提交。

## 接口

`GET /admin/announcements` 要求管理密钥，直接返回上述 JSON，使用 `Cache-Control: no-store`。读取失败时弹窗显示错误并提供重试，用户仍可关闭后使用工作台。公告不从第三方站点读取，也不会把管理密钥发送给 GitHub。
