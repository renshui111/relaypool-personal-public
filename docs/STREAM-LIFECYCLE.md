# 流式连接释放与读取优化

2026-11-09，本轮针对共用空闲超时读取器，覆盖 WorkBuddy、兼容 API、原生及部分订阅渠道的调用路径。

## 修复与改进

- 原实现超时后仅通知外层停止等待，依赖外层随后关闭连接。现在超时立即关闭底层响应体，释放阻塞读取。
- 原实现只保证关闭通知执行一次，底层 `Close()` 仍可能被反复调用。现在超时、用户取消和流清理共用同一次底层关闭，并向重复调用者返回相同结果。
- 同一条流的读取按顺序执行，各次读取使用独立结果通道，避免并发读取串用结果。
- 缓冲区在已完成的读取之间复用，减少重复分配；迟到的读取只会修改私有缓冲区，不触碰调用方已复用的内存。
- 关闭或 EOF 后不会继续发起底层读取；零长度读取也不创建后台任务，最后一块数据随 EOF 正常返回。

保持原空闲超时时间和关闭超时功能时的直通行为。这是每次读取的空闲期限，不是限制整个长回复的总时长。底层 HTTP 响应体应遵守关闭可中断读取的约定；任意不响应关闭的自定义 Reader 无法由 Go 强行终止。

## 验证

新增测试覆盖：无需外层清理的超时关闭、迟到读取不修改调用者内存、关闭后不再读、32 次并发关闭只关闭一次且错误一致、64 路并发读取无丢失或重复、空读取、最后一块数据及 EOF、禁用超时时保持直通。继续运行已有流关闭传播和后台任务泄漏检查。
